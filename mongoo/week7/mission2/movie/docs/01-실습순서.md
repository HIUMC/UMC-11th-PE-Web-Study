# 01. 워크북 실습 순서

1. **ERD/DB**: `02-ERD.md`를 읽고 member/rating/favorite 관계를 확인한다. 이미 입력한 DB는 유지하고 `sql/03-verify.sql`로 조회한다.
2. **새 Spring 프로젝트**: Spring Boot 3.5.0/Java 21/레이어 패키지를 사용한다. `application.yaml`은 직접 만든 umc_movie_week5를 가리킨다.
3. **API 명세**: `03-API명세.md`의 GET 3개와 응답 DTO를 확인한다.
4. **실습 0 CORS 오류 관찰**: 본인이 기존 Vite를 잠시 종료한 뒤 `../mock-frontend`를 5173에서 실행한다. 백엔드의 CORS를 끄고 요청해 Console 오류를 확인한다. 이 간이 HTML은 임시 관찰용이다. 실행 명령과 원래 서버 복구는 README 6번을 따른다.
5. **Entity**: BaseTimeEntity → Member → Rating 순으로 코드를 읽는다. Favorite은 스키마만 만들고 Java 코드는 8주차에 작성한다.
6. **Repository**: existsByNickname/existsByEmail, findByMember_MemberIdOrderByRatingIdDesc를 확인한다.
7. **DTO**: available 응답과 RatingResponse의 6개 필드를 확인한다. Entity/password는 응답하지 않는다.
8. **실습 1~3**: Controller → Service → Repository 흐름으로 API 3개를 구현하고 Postman에서 확인한다.
9. **CORS 설정 후 확인**: localhost:5173을 허용하는 설정을 켜서 간이 HTML의 같은 요청이 성공하는지 확인한다. 간이 서버를 종료한다.
10. **필수 미션**: 기존 `week5/mission1/umcine` Vite를 다시 실행한다. 영화 상세의 기존 내 평점 영역에서 `회원 정보 확인 · 평점 불러오기`를 펼쳐 API 3개를 호출한다. 새 페이지는 만들지 않는다.
11. **제출 기록**: 실제 화면과 Network, Postman의 URL·JSON 캡처 및 핵심 코드를 `06-미션제출기록.md`에 맞춰 정리한다.

## 오류 확인

- DB 접속 오류: MySQL 실행 상태, 계정/비밀번호/DB 이름을 확인한다.
- 스키마 검증 오류: SHOW CREATE TABLE로 컬럼과 매핑을 비교한다. 데이터를 무작정 삭제하지 않는다.
- 5173 사용 중: 기존 UMCine가 실행 중일 수 있다. 서버를 중복 실행하지 않는다.
- 브라우저에서만 요청 실패: 실제 요청 URL/Origin/HTTP 상태/Console/CORS 응답 헤더를 확인한다.
- localhost와 127.0.0.1은 서로 다른 Origin이다. 브라우저는 http://localhost:5173으로 연다.
