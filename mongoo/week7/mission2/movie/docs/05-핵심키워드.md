# 05. 핵심 키워드 정리

## SOP와 CORS

Origin은 scheme(프로토콜), host, port의 조합이다. http://localhost:5173과 http://localhost:8080은 포트가 달라 cross-origin이다.
SOP는 다른 출처의 데이터를 스크립트가 자유롭게 읽는 것을 제한한다. CORS는 서버가 응답 헤더로 허용 출처를 알려 브라우저가 그 응답을 읽게 하는 체계다. 읽기 허용은 사용자 인증/접근 권한 검사를 대체하지 않는다.
참고: [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).

단순 GET은 실제 요청이 서버에 도착한 뒤 브라우저가 응답 읽기를 막을 수 있다. 반면 preflight가 필요한 요청은 사전 OPTIONS가 실패하면 실제 요청이 전송되지 않는다. 따라서 “CORS는 언제나 요청을 막지 않는다”는 표현에는 예외가 있다.
또한 잘못된 URL/Origin, 리다이렉트, 프록시, 서버 오류도 CORS 진단에 영향을 줄 수 있어 항상 백엔드 설정 하나만 원인이라고 단정하지 않는다.
참고: [MDN CORS 오류](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS/Errors).

## Same-Origin과 Same-Site

Same-Origin은 scheme/host/port를 모두 비교한다. 현대 브라우저의 schemeful same-site는 scheme과 등록 가능한 도메인을 비교한다. 포트나 서브도메인이 달라도 same-site일 수 있지만 http/https가 다르면 cross-site가 될 수 있다.
따라서 같은 localhost의 서로 다른 포트는 cross-origin이면서 same-site일 수 있다. CORS와 쿠키 SameSite는 판단 목적이 다르다.
참고: [MDN Sec-Fetch-Site](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Site).

## 쿠키의 SameSite

Strict는 same-site 요청에 제한적으로 쿠키를 보내고, Lax는 일부 최상위 탐색 등 예외를 허용한다. None은 cross-site 전송을 허용하며 Secure가 필요하다. 실제 전송에는 credentials 설정과 브라우저의 서드파티 쿠키 정책도 영향을 준다. SameSite=None이나 CORS 허용만으로 전송이 무조건 보장되지는 않는다.
이번 주는 쿠키 인증을 구현하지 않아 설정하지 않는다.
참고: [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie).

## 복합 UNIQUE 제약

회원 1이 영화 550/155에 각각 평점을 남기는 것과 회원 2가 영화 550에 평점을 남기는 것은 허용한다. (회원 1, 영화 550) 조합이 두 번 저장되는 것은 막는다. 각 컬럼을 개별 UNIQUE로 만들면 회원 한 명이 여러 영화를 평가할 수 없게 된다.
애플리케이션의 사전 중복 확인만으로는 동시에 들어온 요청을 완전히 막지 못하므로 DB 제약이 최종 무결성을 보장한다.
참고: [MySQL CREATE TABLE](https://dev.mysql.com/doc/refman/8.4/en/create-table.html).

## API Key는 어디에 두는가

브라우저 번들/Network에 포함된 키는 사용자가 확인할 수 있다. 프론트의 환경 변수에 넣었다고 비밀이 되는 것은 아니다. 비밀 키/권한이 큰 자격 증명은 백엔드에 보관하고 필요한 기능만 제한해 제공한다. 브라우저용 공개 키는 공급자의 사용 정책과 제한 기능을 확인한다.
워크북은 영화 데이터에 대해 프론트에서 TMDB를 직접 호출하는 구조를 선택했다. 이 구조에서는 브라우저에 포함된 자격 증명을 비밀로 취급할 수 없다는 점을 알아야 한다. 이번 백엔드 API 3개와 제공 화면은 TMDB 키 자체를 요구하지 않는다.
참고: [TMDB 인증](https://developer.themoviedb.org/docs/authentication-application).

## Spring에서의 적용

WebMvcConfigurer.addCorsMappings로 정책을 한 곳에 모았다. 이번 API 경로 /members/**에 localhost:5173만 허용했다. 다른 Origin에서 읽도록 하려면 실제 화면의 Origin을 명시적으로 추가해야 한다.
참고: [Spring MVC CORS](https://docs.spring.io/spring-framework/reference/web/webmvc-cors.html).
Gradle은 Spring Boot 3.5 지원 범위인 8.x로 고정했다.
참고: [Spring Boot 3.5 시스템 요구사항](https://docs.spring.io/spring-boot/3.5/system-requirements.html).
