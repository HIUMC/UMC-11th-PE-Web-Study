# 07. 검증 결과와 복구 기록

## 기존 구현 검증

Spring Boot 3.5.0 / Java 21 / Gradle 8.14.3에서 자동 테스트 13개와 test bootJar가 통과했다. 이 자동 테스트 DB는 H2다.
닉네임/이메일 중복·신규, 회원별 평점 필터·정렬·DTO, 빈 목록, 없는 회원 404, 잘못된 회원 번호 400, CORS 허용·거부·preflight와 비활성화 시 헤더를 확인했다.

## 실제 실행 중인 API 확인 (2026-10-26, Asia/Seoul)

localhost:8080에 이미 실행된 Spring 서버에 읽기 전용 GET을 보냈다. 서버를 재시작하거나 DB 데이터를 변경하지 않았다.

| 요청 | 실제 결과 |
|---|---|
| /members/nickname/수현 | 200, available=false |
| /members/nickname/new-user-2026 | 200, available=true |
| /members/email/noco@umc.com | 200, available=false |
| /members/email/new-user-2026@example.com | 200, available=true |
| /members/1/ratings | 200, ratingId 3(movie155) → 2(movie550) |
| /members/999999999/ratings | 404 |

Origin: http://localhost:5173 요청의 응답에 Access-Control-Allow-Origin: http://localhost:5173을 확인했다. API를 통한 실제 응답 확인이며 별도 MySQL 관리자 접속으로 DB 내용을 교정하거나 검증한 것은 아니다.

## 잘못 만든 화면 복구

처음에 만든 독립 frontend/ 데모는 워크북 필수 미션의 기존 실제 화면을 대체할 수 없었다. 그 데모와 실행 스크립트, 해당 화면의 H2 스크린샷은 프로젝트에서 분리해 임시 백업으로 옮긴다. 제출 인증으로 사용하지 않는다.
5173의 데모 Python 서버를 종료하고 기존 week5/mission1/umcine Vite를 복구했다. 프론트엔드 채팅의 피그마 캡처 4장(목록/검색/검색 결과/상세)을 확인했다.
사용자의 '새 화면을 추가하지 말라'는 지시에 따라 기존 상세의 내 평점 영역에만 접이식 회원 확인 항목을 추가한다. 기존 목록/검색/헤더/출처 및 TMDB 호출은 유지한다.

## 최종 실제 화면 확인

최종 UI 검증 결과는 복구 적용 후 이 문서에 추가한다. 이 문서의 자동 테스트 결과는 본인의 실습 인증/회고/Notion 제출 완료를 뜻하지 않는다.
