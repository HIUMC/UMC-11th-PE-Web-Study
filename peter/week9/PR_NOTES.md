# 9주차 백엔드 PR 작성 메모

PR을 작성할 때 아래 내용을 다시 확인하고 사용자에게 리마인드한다.

## 워크북 실습과 필수 미션 구현

- Swagger 설치와 공개 경로 설정, 회원가입·로그인 문서화, 즐겨찾기 등록 문서화 및 JWT 인증 표시를 구현했다.
- 평점 등록·PATCH 수정·PUT 교체·삭제·회원별 조회, 내 정보 조회·수정, 즐겨찾기 목록·여부·해제에 설명, 인증 필요 여부, 응답 상태와 오류 코드를 문서화했다.
- 평점 중복 등록 RATING409_1과 다른 회원의 수정 RATING403_1을 검증하는 단위 테스트 2개를 구현했다.
- 토큰 없는 평점 등록 401과 유효한 토큰의 평점 등록 201을 검증하는 통합 테스트 2개를 구현했다.

## 최소 요구사항을 보완한 구현과 이유

- Swagger에서 서버가 토큰으로 결정하는 회원 ID를 직접 입력하는 혼동을 방지하기 위해 인증 회원 ID 파라미터에 Parameter(hidden = true)를 구현했다.
- 실제 API 계약과 문서의 일치를 위해 즐겨찾기 등록의 400·404 응답과 인증 실패 코드 종류를 추가로 문서화했다. 워크북 등록 예제의 응답은 201·401·409다.
- 문서 경로가 인증 설정 변경으로 차단되는 회귀를 발견하기 위해 토큰 없이 /v3/api-docs를 조회하는 통합 테스트를 구현했다. 워크북 Spring 본문에도 포함된 보완 검증이다.
- 오류 발생 후에도 데이터 상태가 보존되는지 확인하기 위해 평점 단위 테스트에 저장 호출 차단과 기존 점수·후기 보존 검증을 구현했다.
- 평점 등록 API의 응답과 저장 결과를 함께 검증하기 위해 인증 통합 테스트에 DB 저장 건수·영화 ID 검증을 구현했다.

## 이전 주차에서 이어받은 구현

- 평점 PUT 및 PATCH의 생략값·명시적 null 구분, 업무 오류 Enum, DB UNIQUE 위반 분류는 8주차 소스에서 이어받은 구현이다.
- 기존 PUT 교체 API의 사용 방법을 설명하기 위해 9주차 Swagger에 PUT과 PATCH의 수정 계약을 각각 문서화했다.
- 회원가입·평점·즐겨찾기의 추가 통합 테스트, DB 제약 위반과 트랜잭션 롤백 검증은 이전 주차에서 이어받은 테스트다. 이번 필수 미션에서 새로 작성한 것으로 표현하지 않는다.
- 선택 미션 제출에 필요한 트랜잭션 제거 전후 캡처는 진행하지 않았다.

## 검증과 제출

- 테스트는 H2 메모리 DB로 실행한다. 실제 MySQL 검증과 구분해 기재한다.
- 실습 6에서 중복 검사를 주석 처리했을 때 오류 코드 차이를 테스트가 발견했다. 캡처 완료 후 해당 검사를 복구했다.
- 필수 제출물은 문서화한 Swagger 화면 캡처, 평점 테스트 코드, 테스트 전체 통과 화면이다.
